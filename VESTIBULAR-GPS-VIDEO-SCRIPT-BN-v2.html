রেকর্ড করার আগে অবশ্যই
  • Live site hard-refresh করো: Ctrl + F5। পুরনো ক্যাশ ধরে রাখলে ভুল version রেকর্ড হয়ে যাবে।
  • Camera দেখাবে বলে থাকলে permission আগেই allow করে রাখো — কিন্তু voice-over-এ স্পষ্ট বলবে camera শুধু head motion মাপে, gaze/VOR নয়।
  • Simulation label আর LIVE SENSOR label গুলিয়ে ফেলবে না। পর্দায় যে label আছে, মুখে সেই label-ই বলো।
  • OSI-র জন্য অন্তত ৩টি baseline session capture করো। একবার click দিয়ে final score দাবি করবে না — তিনটির কম হলে index প্রাথমিক অবস্থায় থাকে।
  • Console দেখানোর আগে চোখে দেখে নাও প্রতিটি domain row-এর রঙিন tag পড়া যাচ্ছে — SIMULATED = বেগুনি, MEASURED = সবুজ, REPORTED = হলুদ, UNAVAILABLE = ধূসর। ভিডিওতে এটাই তোমার সততার প্রমাণ।
  • Screen recording 1080p, browser zoom 100%, আর cursor যেন গুরুত্বপূর্ণ UI ঢেকে না রাখে।

১. সূচনা / Opening

পর্দায়Live website খুলে hero দেখাও — astronaut, দূরের Earth, HUD আর title একসাথে ফ্রেমে রাখো।
ভয়েস-ওভার“এটি VESTIBULAR GPS — একটি offline-first, browser-based astronaut sensorimotor readiness prototype। দীর্ঘ space mission বা gravity transition-এর পর astronaut-এর balance, head motion, task performance ও motion symptoms নিজের baseline-এর সঙ্গে তুলনা করে দেখানোই এর উদ্দেশ্য। এটি medical device বা NASA-certified clinical instrument নয়; এটি NASA-relevant science থেকে তৈরি একটি transparent proposed prototype।”
গুরুত্বপূর্ণ ভিজ্যুয়াল নোট

Astronaut বড় ও viewer-facing থাকবে; Earth/Moon/Mars দূরের background reference। কোন planet যেন astronaut-এর সামনে foreground globe হয়ে না আসে।

0:15 – 0:32

২. Intro ও hero / Scene layer

পর্দায়Intro overlay-তে ENTER THE EXPERIENCE চাপো। তারপর hero-তে title, floating astronaut, দূরের Earth এবং ডান দিকের science card দেখাও।
ভয়েস-ওভার“প্রথম screen-এ একসাথে তিনটি জিনিস দেখি — space context, astronaut subject, আর vestibular science-এর সংক্ষিপ্ত সারমর্ম। Astronaut প্রথমে viewer-এর দিকে মুখ করে; পরে microgravity mode-এ ধীর drift বা slow rotation হতে পারে। Mouse movement-এ scene respond করে।”
কী বোঝাবেএটি presentation layer। এটি নিজে কোনো medical reading নয়। Real NASA ACES suit GLB এখানে visual subject হিসেবে ব্যবহার হয়েছে; procedural lighting ও material detail suit-কে readable করে তোলে।
0:32 – 0:49

৩. Body section / Sensory arbitration

পর্দায়#sec-body-তে scroll করো। তিনটি sensory input card, subjectCanvas, body axes, centre-of-gravity ও sensory-weight control দেখাও।
ভয়েস-ওভার“Balance একক কোনো sensor-এর ফল নয়। Vision, vestibular system আর proprioception — এই তিনটি input পরস্পর conflict করলে spatial disorientation বা motion sickness-এর মতো সমস্যা হতে পারে। এই section-এ আমরা weight বদলে model-এর arbitration behaviour দেখি। এটি একটি conceptual model, পূর্ণ biomechanical measurement নয়।”
টেস্টতিনটি weight slider বদলাও, subject-এর lean ও indicator-এর পরিবর্তন দেখাও। Voice-over-এ বলবে — এটি input weighting demonstration, clinical sway measurement নয়।
0:49 – 1:07

৪. Inner-ear section / Canal ও otolith

পর্দায়#sec-ear-এ যাও। তিনটি semicircular canal, utricle, saccule, otoconia, nerve pulse এবং yaw/pitch/roll control দেখাও।
ভয়েস-ওভার“তিনটি semicircular canal মাথার angular acceleration-কে আলাদা আলাদা plane-এ sense করে। Utricle ও saccule linear acceleration এবং tilt-এর সঙ্গে সম্পর্কিত otolith response দেখায়। এখানে rotation slider নাড়ালে canal signal বদলায়, আর gravity mode বদলালে otolith visualization বদলায়।”
টেস্ট ক্রম১) Yaw slider নাড়াও → ২) Pitch/roll বদলাও → ৩) label toggle করো → ৪) reset চাপো → ৫) Earth/Moon/Microgravity mode বদলে otolith response দেখাও।
Truth label

এটি anatomically informed explanatory 3D model; patient-derived scan বা clinical simulator নয়।

1:07 – 1:21

৫. Brain section / Pathway

পর্দায়#sec-brain-এ যাও। NIH brain model এবং nerve → vestibular nuclei → cerebellum → thalamus → cortex pathway দেখাও।
ভয়েস-ওভার“Vestibular signal শুধু inner ear-এ শেষ হয় না। Signal brainstem nuclei, cerebellum, thalamus এবং cortex-এর দিকে এগোয়। এই section-এ real NIH anatomical brain asset-এর ওপর pathway pulse দেখানো হয় — এটি source-backed anatomy visualization, কোনো individual brain diagnosis নয়।”
অ্যাট্রিবিউশনপর্দায় NIH 3D model ও CC-BY 4.0 attribution দেখাও — Research section-এ এটি আছে।
1:21 – 1:35

৬. VOR section / সীমা এখানেই

পর্দায়#sec-vor-এ যাও। target reticle, head/eye trace, gain control ও gaze-error display দেখাও।
ভয়েস-ওভার“VOR হলো মাথা নড়লেও চোখকে target-এর ওপর স্থির রাখার reflex। এই canvas-এ VOR concept এবং head/eye সম্পর্ক visualise করা হয়। কিন্তু বর্তমান webcam provider eye landmarks মাপে না — তাই live camera mode-এ real VOR gain দাবি করা যাবে না। প্রকৃত eye–head measurement-এর জন্য vHIT বা eye-landmark provider প্রয়োজন।”
টেস্টfrequency / amplitude / gain slider বদলাও, target lock ও trace observe করো। Voice-over-এ স্পষ্ট বলবে — এই section-এর animation educational model, camera-only live VOR measurement নয়।
1:35 – 2:00

৭. Sensors section / তিনটি source

পর্দায়#sec-sensors-এ যাও। source button, permission control, simulator, chart, attitude gauge ও recorder দেখাও।
ভয়েস-ওভার“এখানে source নির্বাচন করা যায় — SIMULATION, LIVE SENSOR অথবা REPLAY। Simulation হলো deterministic generated signal; Live Sensor হলো browser-এর DeviceOrientation/DeviceMotion permission দেওয়ার পরে আসা real device data; আর Replay হলো আগে রেকর্ড করা session। UI সব সময় source label দেখায়।”
Test ASimulation চালু রেখে motion script চালাও, yaw/pitch/roll chart ও HUD rate দেখাও। এটাকে live human measurement বলবে না।
Test BMobile বা HTTPS-এ permission button চাপো, phone tilt করো, attitude gauge/chart-এর পরিবর্তন দেখাও। Physical device-এর accuracy varies — এটিকে lab-grade IMU বলবে না।
2:00 – 2:28

৮. Camera scan ও realtime output / Camera pipeline

পর্দায়#sec-integration-এ যাও। START CAMERA SCAN চেপে permission allow করো। Preview, analysis buffer, status, samples, analysis rate, live head motion ও signal quality দেখাও।
ভয়েস-ওভার“Camera pipeline-এর সব processing এই device-এ হয়। User-facing preview high resolution; আর estimator আলাদা ৬৪×৪৮ analysis buffer-এ প্রায় ১৮ Hz-এ consecutive frame block-match করে global head motion, motion energy, residual jitter ও displacement বের করে। কোন video কোথাও upload হয় না।”
CalibrationCALIBRATE চেপে প্রায় ২.২ সেকেন্ড স্থির থাকো — এটি device-এর noise floor মাপে। এরপর মাথা সামান্য নাড়াও; LIVE HEAD MOTION, motion energy, jitter ও signal quality-র পরিবর্তন দেখাও।
Truth boundary — এটাই সবচেয়ে গুরুত্বপূর্ণ স্বীকারোক্তি

“এই camera head motion মাপে, gaze নয়। তাই LIVE EYE–HEAD / VOR field UNAVAILABLE দেখাবে। এটি limitation — কিন্তু লুকানো নয়। এটাই honest output।”

2:28 – 2:42

৯. Gravity / Microgravity / Environment

পর্দায়#sec-space-এ যাও। Earth, Moon, Mars, Microgravity button; otolith load, canal signal, free-float model ও adaptation timeline দেখাও।
ভয়েস-ওভার“Environment button বদলালে scene-এর gravity context বদলায়। Earth ১ g, Moon প্রায় ০.১৬ g, Mars প্রায় ০.৩৮ g, আর Microgravity প্রায় ০ g — model হিসেবে। Earth/Moon/Mars background reference object; তারা subject-এর সামনে এসে content ঢেকে দেয় না।”
টেস্টEarth → Moon → Mars → Microgravity click করো। Button state, astronaut-এর motion, otolith response ও timeline phase-এর পরিবর্তন দেখাও।
2:42 – 2:58

১০. Lab tests / Interactive task

পর্দায়#sec-lab-এ যাও। চারটি demonstration card থেকে test select করো। প্রতিটি card-এর WHAT / WHY / HOW / SOURCE পড়ে সংক্ষেপে বলো।
ভয়েস-ওভার“Lab section-এ ছোট ছোট interactive task আছে। এগুলো OSI domain-এর prototype input তৈরি করে — কিন্তু physical astronaut physiology-এর replacement নয়।”
সুপারিশকৃত টেস্টReaction-time task নাও। Burst/arrow cue এলে matching arrow key চাপো। অন্তত ৩–৫ trial করো। পরীক্ষা শেষে measured reaction time task_perf হিসেবে Console-এ যায় — পর্দায় দেখাও যে tag এখন MEASURED হয়ে গেছে, কারণ মানটি সত্যিই এই সেশনে তুমি তৈরি করেছ।
2:58 – 3:38 · CORE

১১. Mission Console / OSI / product-এর হৃদয়

পর্দায়#sec-console-এ যাও। প্রথমে source label দেখাও। তারপর CAPTURE BASELINE SESSION button, coverage ও domain card-এ zoom করো।
ভয়েস-ওভার“এটাই VESTIBULAR GPS-এর core product। OSI — Orientation Stability Index — subject-এর নিজের baseline থেকে deviation বোঝায়। ১০০ মানে নিজের baseline-এর কাছে; ১০০ মানে medically healthy নয়।”
Baseline টেস্টSimulation চালু রাখো অথবা available sensor চালাও। CAPTURE BASELINE SESSION অন্তত তিনবার চাপো। Counter, coverage ও domain row দেখাও। তারপর নতুন motion বা task input দিলে z-score, sub-score, OSI, CI95 ও MDC95 কীভাবে update হয় দেখাও।
ফর্মুলাmedian/MAD baseline → direction-aware robust z-score → 100·exp(−|z|/4.48) sub-score → available-domain weighted OSI → bootstrap CI → MDC95 → advisory → countermeasure → recheck।
OutputClear / Mitigate / Escalate advisory, crew authority, comm-delay rule, top deficient signal, ranked countermeasure ও recheck verdict। Missing channel থাকলে coverage কমবে — fake 0 বা fake eye score কখনো আসবে না।
যেটা ভুলে যাওয়া যাবে না

বর্তমান camera-only run-এ eye_head unavailable থাকবে, কারণ webcam gaze মাপে না। পূর্ণ ৬-domain score দেখাতে lab task, symptoms, IMU/ingest এবং eye-landmark বা vHIT data দরকার। Coverage সংখ্যাটা পর্দায় সৎভাবে দেখাও — লুকিও না।

৩০ সেকেন্ডের cut-এর জন্য এই section থেকেই সবচেয়ে বেশি নাও — Coverage / OSI / advisory এই তিনটি মুহূর্ত।

3:38 – 3:52

১২. Integration / real hardware path / Data flow

পর্দায়#sec-integration-এ A-TO-Z DATA FLOW, provider table, instrument mapping ও LIVE INGEST JSON দেখাও।
ভয়েস-ওভার“Real instrument connection-এর জন্য website তিনটি path দেখায়। Browser-native sensor আজই চালানো যায়। Force plate, IMU বা vHIT-এর জন্য local bridge contract documented আছে — serial/USB/BLE বা vendor SDK থেকে JSON/WebSocket bridge। আর file বা manual ingest দিয়ে একই schema test করা যায়।”
সাতটি ধাপSENSE → INGEST → BASELINE → INDEX → ADVISORY → ACT → RECHECK। এই loop-টাই dashboard-কে monitor বানায়।
JSON টেস্টসঠিক sample payload ingest করো। তারপর malformed JSON বা wrong schema দিয়ে rejection দেখাও। বলবে — strict validation ভুল health number-এর চেয়ে explicit error-কেই ভালো ধরেছে।
3:52 – 4:00

১৩. Research ও সমাপ্তি / Closing

ভয়েস-ওভার“প্রতিটি scientific statement source registry-তে traceable। NASA research project, sensorimotor risk framework, CIPHER vestibular study এবং NIH/NCBI anatomy reference এখানে দেখানো আছে। OSI একটি proposed prototype; weights heuristic; clinical validation-এর কোনো দাবি করা হচ্ছে না। আমাদের লক্ষ্য — NASA-relevant science-কে astronaut-facing decision workflow-এ স্বচ্ছভাবে দেখানো।”

“VESTIBULAR GPS does not pretend to replace a laboratory. It shows how real signals, personal baseline, uncertainty and crew authority can meet in one offline mission interface.”
